# ТЗ: разработка игры с карточными пасьянсами на Flutter (MVP)

## 1. Цель
- Разработать кроссплатформенную офлайн-игру с карточными пасьянсами на Flutter.
- Обеспечить стабильный игровой процесс, понятный UI и расширяемую архитектуру.

## 2. Платформы
- Android
- iOS
- Web

## 3. Игровые режимы MVP
- Косынка (Klondike, режимы draw-1 и draw-3)
- Паук (Spider, 1 масть в MVP)
- Свободная ячейка (FreeCell)

## 4. Обязательная локализация
- Игра должна быть полностью на двух языках: русский и английский.
- Язык при первом запуске определяется автоматически по системному языку.
- В настройках доступен ручной выбор языка.
- Локализуются все строки: меню, кнопки, подсказки, ошибки, статистика, onboarding.
- Строки в UI не хардкодятся, используются только ресурсы локализации.

## 5. Функциональные требования
- Новая игра, рестарт, автозавершение.
- Проверка валидности ходов по правилам каждого пасьянса.
- Подсказка хода (Hint), Undo/Redo.
- Счет, таймер, статистика (победы, лучший результат, серия побед).
- Сохранение текущей партии и восстановление после перезапуска.
- Настройки: звук, вибрация, тема, язык, внешний вид карт.

## 6. Нефункциональные требования
- Плавность интерфейса: целевые 60 FPS.
- Быстрый запуск приложения.
- Разделение UI и бизнес-логики.
- Покрытие тестами core-логики не ниже 80%.

## 7. Архитектура
- Подход: feature-first.
- Слои:
  - presentation
  - domain
  - data
- State management: Riverpod.
- Движок правил хранится отдельно и не зависит от UI.

## 8. Структура модулей
- core/
- features/solitaire_selector/
- features/klondike/
- features/spider/
- features/freecell/
- features/stats/
- features/settings/
- shared/widgets/

## 9. UX/UI
- Управление: drag&drop и tap-to-move.
- Подсветка допустимых ходов.
- Анимации перемещения карт 120–220 мс.
- Адаптивный layout для мобильных и desktop-экранов.
- Поддержка базовой доступности (контраст, масштаб текста).

## 10. Логика и алгоритмы
- Генератор раздач с seed для воспроизводимости.
- Проверка доступных ходов для подсказок.
- Проверка состояния победы.
- Undo через стек изменений состояния.

## 11. Хранение данных
- Локальное сохранение партии, статистики и настроек.
- Формат хранения должен поддерживать восстановление состояния без потери прогресса.

## 12. Тестирование
- Unit-тесты для правил каждого пасьянса.
- Widget-тесты ключевых экранов.
- Smoke-проверки локализации RU/EN.
- Проверка отсутствия UI overflow на длинных английских строках.

## 13. Этапы реализации
1. Каркас приложения, тема, навигация, модели карт.
2. Реализация движка правил и Косынки.
3. Добавление Паука и FreeCell.
4. Статистика, настройки, локализация RU/EN.
5. Оптимизация, тесты, полировка UX.
6. Релиз-кандидат и исправление багов.

## 14. Критерии готовности
- Все 3 пасьянса играбельны по правилам.
- Корректно работают RU и EN локализации.
- Прогресс партии корректно сохраняется и восстанавливается.
- Все обязательные тесты проходят.
- Критические баги отсутствуют.

## 15. Дополнительная креативная фича
- Daily Challenge: ежедневная seed-раздача с локализованным описанием и локальными рекордами (время/ходы).
